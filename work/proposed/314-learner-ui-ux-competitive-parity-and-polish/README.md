# 314 — Learner UI/UX Competitive Parity and Polished Cross-Platform Study Experience

> **Status:** Proposed
> **Owner:** `implementation`
> **Created:** 2026-09-11
> **Depends on:** WI310

## Why this work item exists

SkillForge already has the functional pieces of a serious certification-prep product. The next gap is not another feature checkbox; it is making those pieces feel coherent, obvious, fast, accessible, and native enough that the user does not have to learn the application's structure before they can study.

The parity target is the quality of the workflow, not visual imitation. SkillForge keeps its own identity and its offline-first, no-account, local-data advantages.

## Acceptance criteria

- [ ] **UX-001** — perform a task-based public-surface competitive UX review across the complete study workflow.
- [ ] **UX-002** — define and apply one coherent desktop/mobile SkillForge design system.
- [ ] **UX-003** — organize navigation and information architecture around learner questions and next actions.
- [ ] **UX-004** — improve first-run and return-session guidance without repetitive onboarding friction.
- [ ] **UX-005** — make practice, PBQ, flashcard, and mock-exam interaction states consistent and polished.
- [ ] **UX-006** — make readiness/analytics accessible, drillable, and action-oriented rather than decorative.
- [ ] **UX-007** — close responsive/mobile lifecycle, safe-area, keyboard, back-navigation, and touch gaps.
- [ ] **UX-008** — pass manual keyboard and screen-reader acceptance in addition to automated accessibility checks.
- [ ] **UX-009** — establish perceived-performance gates on representative lower/mid-range hardware.
- [ ] **UX-010** — add deterministic visual-regression coverage for important views and states.
- [ ] **UX-011** — run a real-learner usability pilot and disposition high-severity findings.
- [ ] **UX-012** — preserve account-free, offline-capable, telemetry-free-by-default local learner ownership.

## Non-goals

- Copying another prep application's visual design.
- Adding engagement dark patterns or advertising mechanics.
- Requiring cloud identity for ordinary study.
- Treating screenshot aesthetics as usability evidence.
